## Pipeline Bug Fix: Agent Reverting Pre-existing Commits

**Problem:** PR #1714 — fix agent got audit feedback to "revert unrelated changes," diffed against `origin/main`, and reverted Robert's pre-existing landing page + SEO commits (~30 files). Only the agent's 3-file fix survived.

**Root cause:** Audit prompt's "scope creep check" didn't distinguish between agent-introduced changes and pre-existing branch commits. Fix agent treated ALL non-fix commits as scope creep.

**Fix applied:**
1. `audit.md` — Clarified scope creep check: only flag changes the *agent* introduced, not pre-existing commits. Added instruction to check `git log` to distinguish.
2. `fix-feedback.md` — Added rule #6: "CRITICAL — Protect pre-existing commits." Agent must only revert its own commits, never human work.

**Recovery:** Robert needs to cherry-pick commits `415e398` and `bb612bc` back onto main.
